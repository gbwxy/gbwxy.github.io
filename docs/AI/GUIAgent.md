# GUI Agent(ACT)合集


主流GUI产品
聚焦于研发领域的Anthropic Computer Use、通用领域的Browser Use、Manus及OpenAI Operator，以及25.3.31最新发布的AutoGLM-PC沉思版本。一般来说，PC端主要依赖浏览器元素识别或系统API进行交互，而APP端则更多依赖UI解析和视觉检测来执行操作。
PC端：包括Anthropic Computer Use、Browser Use、Manus、OpenAI Operator及AutoGLM-PC。其中AutoGLM-PC「沉思版」于2025.3.31发布，基座模型将于4.14开源，初步评测执行「沉思版」速度较慢。
APP端：智谱AI（美团参投）的AutoGLM表现领先，支持跨APP模糊指令执行，通过语音交互实现全流程操作，具备敏感操作二次确认机制（如支付验证、咖啡偏好确认），操作效率接近真实水平。
另外，可以发现，面向欧美市场的产品更倾向开发PC端，例如Anthropic Computer Use、OpenAI Operator、Browser Use和Manus。而国内市场产品则以APP为主，如腾讯APP Agent、阿里Mobile Agent以及智谱AutoGLM APP。分析可能与国内移动应用生态更加成熟有关，同时反映出国外用户更加习惯使用浏览器访问业务。例如，国外用户通常会登录相关公司官网进行商品购买，而国内用户更倾向于通过综合电商APP进行购物。但未来PC与移动端界限可能变的模糊，最终可能演变为“多端自适应”的新一代GUI Agent范式。

Agent（AI Agent核心模块）
任务决策，负责接收任务、协调其它组件等。通过服务初始化时动态注册浏览器操作能力（如点击、输入操作），实现高效扩展。
BrowserContext（浏览器交互）
获取页面结构（如DOM 结构、截图）并执行指令，主要基于 Playwright 获取DOM，同时支持多标签页管理和跨浏览器兼容（如Chrome、Firefox、Edge）。
MessageManager（消息管理）
将浏览器状态转化为大模型可理解的提示语，同时维护历史记录等。例如将页面元素标记为结构化数据，方便模型解析。
LLM（大语言模型）
将自然语言转化为动作指令，主要通过 LangChain 接入 GPT-4、Claude 等模型，同时通过工具调用（Function Calling）生成 JSON 格式指令。
Controller（动作控制器）
借助 Playwright 完成各种底层任务（比如点击按钮、输入文字），自带重试机制应对任务异常等情况。此外，支持扩展自定义动作。

从技术实现分类
当前主要有三类技术实现体系（硬件操作系统不在此次讨论范围）:
页面解析 + 大模型理解：如Android XML解析、WEB页面DOM节点解析，该技术以腾讯APPAgent V1及WEB端Browser Use为代表，实现成本相对较低、但多平台泛化性欠缺。
视觉检测 + 大模型理解：如OCR识别文字，GroundDino理解icon坐标，该技术属于当前主流，以阿里Mobile Agent为代表，实现成本适中，需使用小模型及大模型进行图像及文字有效定位。
创新工程：使用强化学习实现任务自进化、（Set-of-Marks）理解图像、任务规划等，以智谱 AutoGLM 为代表，实现成本较高，需要深入到算法模型层进行大量训练及底层改造。

界面元素有效识别

网页动态识别元素存在困难，尤其对于个性化表单存在识别错误、按钮漂移等问题，部分产品采用高分辨率视觉模型进行解决。

国内APP应用迭代频率较高、UI更新相对频繁，因此Agent通过预学习、知识库建设、算法能力建设等提升识别有效性。

长流程任务处理

跨应用操作易中断，此问题为通用问题，即便是Browser Use，也被用户吐槽任务容易中断，部分产品采用专用子模块跟进子任务的执行进度。

通过分层架构（分离规划与执行）、反思模块（确认任务是否成功）、强化学习提升成功率。

计费成本控制

PC图像通常分辨率较高，对于GPU算力需求高，预计同等情况下花费高于APP版本。

相比PC场景，推理成本略低，但在任务规划等场景下调用大模型成本仍然较高。














其中核心能力分为三块：
①视觉感知：识别各个终端屏幕元素，通过Android、IOS及PC端的UI页面解析能力、OCR算法识别文本以及各类检测模型实现对屏幕内容的高效感知及定位，感知内容可存储至数据库（如向量数据库）。
②理解规划：自主观察、学习及持续反馈迭代提升任务规划精准度。1）通过视觉大模型（例如GPT-4V）理解学习屏幕的图片内容，识别界面元素并保存至数据库最新趋势直接对视频流进行学习，获取更精准内容；2）保存长流程任务状态数据（如使用向量数据库），为多任务切换时的意图识别提供高质量上下文；3）多智能体协作反馈，提升多任务（APP或PC组件）交互理解、跳转及任务理解准确度，根据反馈结果进行规划调整。
③仿真执行：业内实践，Android、Windows等均已跑通任务的执行流程，通过调用各个终端API进行操作。1）定义自定义函数，实现滑动、点击等拟人操作；2）通过各类桥接库（如Android adb接口）或其它API进行最终的Action操作。
